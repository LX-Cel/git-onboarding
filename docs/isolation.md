# 练习环境与隔离边界

目标是让真实 Git 和完整 Bash 的练习不接触用户 Windows 文件、凭据和已有开发发行版。普通临时目录和默认 WSL 都不满足这一目标。

## 已实现

1. 每份应用数据创建 UUID 命名的专用 WSL 2 发行版。发行版名和本机路径写入所有权记录，仅操作该发行版。
2. 镜像在首次导入前就写入 `wsl.conf`：关闭 Windows 磁盘自动挂载、fstab 挂载、Win32 互操作和 Windows PATH 注入。
3. 终端和课程引擎以 `student`（UID 1000）运行，不提供 sudo。
4. 每个进程在 bubblewrap 新的用户、挂载、PID、网络等命名空间内运行；移除全部 capabilities，启用 no-new-privileges。
5. 只把学生 Linux home 绑定为可写持久目录。系统工具与课程引擎只读，`/tmp` 为临时文件系统；不挂载 Windows、`/init`、WSL socket、宿主机 `/run`、其他发行版或凭据。
6. 完整 Shell 可以执行镜像已有程序、编辑文件、运行脚本和 Git；运行空间无外部网络，不能安装系统包。它是普通用户 Shell，不是管理员终端。
7. 进程数上限 128，单进程虚拟地址空间 1 GiB，单文件写入上限通过 `ulimit -f 262144` 控制。不会修改用户全局 `.wslconfig`。
8. 编辑器只接受练习仓库的普通文本文件，拒绝路径穿越、隐藏配置、符号链接、设备/FIFO 和超过 256 KiB 的文件；文件描述符使用 `O_NOFOLLOW`。
9. 关闭终端后，PTY relay 终止并回收自己的 Shell 进程组。界面不会把用户输入交给 Windows Shell。

## 边界与限制

- 这不是承诺抵御所有恶意代码的独立硬件安全产品。WSL 与 Linux 内核、Electron、bubblewrap 需要跟进安全更新。
- WSL 2 发行版之间共享 WSL 虚拟机基础设施；本版没有按发行版配置整体 CPU/内存/磁盘配额。已有的每进程限制不能替代整体配额。故不用于执行来源不明的恶意程序或资源压力测试。
- 学生 Shell 可修改自身 home、课程场景元数据和其他练习目录，所以判题用于自学反馈，不是防作弊考试系统。应用不能阻止学习者故意破坏自己练习环境的所有方式。
- 托管练习的分支保护使用本地裸仓库的 pre-receive 钩子，必需检查验证集成树中的练习内容。它们是离线教学规则，不是 GitHub 权限系统或实际 CI 服务。学习者拥有这些练习仓库，规则不构成新的安全隔离边界；保留规则是课程完成条件之一。
- 文件 API 的边界是 Linux 练习环境。进程内路径检查不应被当作针对恶意并发重命名的完整证明；宿主机仍不在挂载范围内。
- 初始化用 root 导入/配置镜像，root 接口不暴露给网页。镜像构建时软件包从 Alpine 官方仓库安装，构建后附带包版本清单。
- 镜像 SHA256 清单防止损坏和意外替换，不能替代安装包代码签名。0.1.0 安装包尚未签名。

## 用户数据

进度由 Windows 主进程保存，练习仓库位于应用专用发行版中。默认不发送遥测、不登录、不上传仓库。初始化系统组件时会访问 Microsoft 下载源；镜像已随安装包提供，练习无需联网。

卸载程序保留练习环境，避免静默丢失成果。后续可增加有明确备份与确认的环境导出、修复和卸载清理界面。
