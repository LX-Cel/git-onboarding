# Git Onboarding · VS Code Git 练习

直接在熟悉的 **Source Control（源代码管理）** 中练习真实 Git。扩展布置任务、提供提示并检查仓库结果；编辑、差异、暂存、提交、分支和合并冲突使用 VS Code 原生功能。

此版支持 **Windows 本地文件夹**。三个单元各提供引导与挑战，共六个场景：

| 单元           | 练习内容                                                 |
| -------------- | -------------------------------------------------------- |
| 你的第一次提交 | 编辑、保存、查看差异、暂存、提交                         |
| 和队友一起开发 | 创建分支、Fetch、真实冲突、合并、Push 到本机练习远端     |
| 从容地修正错误 | 丢弃指定修改、取消暂存保留草稿、在终端用 revert 修正历史 |

## 安装与开始

1. 准备 VS Code 1.95+、[Git for Windows](https://git-scm.com/downloads/win) 和 [Python 3.11+](https://www.python.org/downloads/windows/)。无需安装桌面版 Git Onboarding，也不需要 WSL 或 GitHub 登录。
2. 在 VS Code 的扩展视图 `…` 菜单选择 **从 VSIX 安装 / Install from VSIX**，选择 `git-onboarding-vscode-0.1.1.vsix`。已安装旧版时直接覆盖安装并重新加载窗口，练习文件和提交会保留。
3. 按 `Ctrl+Shift+P`，运行 **Git Onboarding: 开始 / 继续练习**，选择课程与模式。
4. 扩展在新窗口打开专用练习仓库，左侧打开课程文件，右侧自动显示 **Git 练习 · 分步指引**。引导模式逐步说明做什么、在哪里操作、完成后会看到什么；可直接打开文件、源代码管理或终端，然后自己完成操作。
5. 点击 **检查练习结果**，查看本次检查的时间、分支、提交及每项原因。文件尚未保存时会提醒；编辑器中的未保存内容不算已提交。

Python 未被识别时，可在设置中填写 **Git Onboarding: Python Path**，例如 `C:\Python311\python.exe`。此处填写可执行文件路径，不要添加参数。Git 使用 VS Code 内置 Git 扩展识别出的程序；先确认 Source Control 自身可以使用 Git。

## 找到引导与继续学习

- 引导面板关闭后，点击底部状态栏 **练习指引 · 第 N/4 步**，或在命令面板运行 **Git Onboarding: 查看任务与操作指引**。Source Control 的 **Git 练习** 视图顶部也显示当前步骤。
- **上一步 / 下一步**只切换阅读位置，不会替你执行 Git，也不表示通关。面板中的完成条件根据实际仓库更新；完成操作后点击 **检查练习结果**查看详细报告。
- 重新打开同一个练习窗口时，指引自动恢复到上次阅读的步骤。旧版 Markdown 指引标签页也会恢复正文；旧检查报告会要求重新检查，避免把历史报告当成当前结果。
- **独立挑战**默认只显示目标，点击 **展开下一条提示**逐级获取帮助。想跟着完整步骤练习，请在“开始 / 继续练习”中选择 **引导练习**。

## 练习与数据

- 引导与挑战使用不同仓库；重新选择同一练习会继续原有状态。
- 每次手动检查通过后保存完成记录。侧栏条件反映当前状态，历史通过不代表当前仓库始终满足条件。
- 状态变化会自动更新，也可手动检查。恢复课程要求保留未提交草稿，因此它通过时工作区仍可能有更改。
- **归档并重新开始**会先保留旧目录，再创建新练习；未保存文件需要先处理。
- 数据在 VS Code 当前配置文件的扩展存储目录 `LX-Cel.git-onboarding/labs` 下；检查报告显示具体仓库路径，归档在该根目录的 `.archives` 中。
- 扩展不会把你当前打开的普通项目转换为练习。所有初始化和重建限定于有所有权记录的专用目录。
- 这是本地用户权限下的真实 Git 和终端，专用目录不是系统沙箱。练习使用仓库级学习身份与配置，不改用户全局 Git 配置。

## 当前边界

此预览版先验证上述六个场景。桌面版其余课程、Remote WSL、macOS/Linux、真实 GitHub PR 和 Marketplace 发布尚未包含。Source Control 没有覆盖的课程操作可在集成终端完成；扩展不自动替你执行答案。

## 开发与打包

在此目录运行：

```powershell
npm ci --ignore-scripts
npm run prepare:runtime
npm test
$env:VSCODE_EXECUTABLE_PATH = 'E:\Microsoft VS Code\Code.exe'
npm run test:integration
npm run package
```

未指定 VS Code 路径时，集成测试通过官方测试工具下载稳定版。测试使用独立数据目录与练习仓库。VSIX 生成在仓库的 `release/` 下。打包自动复制共享 Python 课程源文件，不将桌面运行镜像或开发依赖打入扩展。

仓库公开可见，当前许可证仍为 `UNLICENSED`。
