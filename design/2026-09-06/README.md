# 工作台方向评审

这三张图是使用内置 image_gen 生成的视觉概念稿，不是已安装应用截图。基于同一场景对比：独立挑战已完成一次真实提交，结果应明确显示完成条件、提交证据和下一步。设计方向待用户选择后再实现；不将图片直接作为应用界面。

## 三个方向

| 方向                                | 布局与气质                                       | 优点                                               | 取舍                                               |
| ----------------------------------- | ------------------------------------------------ | -------------------------------------------------- | -------------------------------------------------- |
| [A 浅色专业工作台](a-workbench.png) | 浅色导航、编辑器上终端下、右侧状态与检查结果     | 适合跨入门、协作、恢复的长期使用；多个状态同时可见 | 大量面板仍有一定工具学习成本                       |
| [B 深色终端优先](b-terminal.png)    | 顶部课程切换；左侧终端，右侧编辑器与结果         | 命令操作集中；适合已有基础的人                     | 深色不是所有人的阅读偏好，初学者提示需更清晰       |
| [C 浅色教学画布](c-learning.png)    | 顶部概念过程；编辑器与终端并排；底部检查与下一关 | 推荐：帮助理解修改、暂存和提交之间的关系           | 协作与恢复关需各自的状态概览，不能硬套三个线性步骤 |

三版都保留完整终端、文件编辑、真实 Git 状态、引导/挑战模式以及可访问的提示。图稿中的命令、图标和字体只是视觉表达，实施时以实际语义校正；特别是 C 的显式命令提示只用于引导模式，挑战模式应隐藏答案。保存、查看差异、提交图和重置入口在详细设计时必须齐全。

## 共同的交互修复

旧按钮复用自动刷新：当前正在轮询时直接返回；状态没变时几乎看不到反馈。截图中 2/2 已通过，却缺少突出的检查结论和下一步。

- 点击后立刻显示「正在检查」，独立读取仓库，不因轮询而丢弃点击。
- 返回通过/未通过条件、可操作原因、提交编号和检查时间。
- 引导练习通过后进入独立挑战；挑战通过后提供下一关；最后一关提供学习路径。
- 编辑器有未保存内容时明确说明检查范围，不把未保存编辑算进提交。
- 失败显示错误与重试入口；支持关闭、Esc 和键盘焦点约束。

本分支先提供独立检查结果窗口的功能修复。三版图中结果区的位置是后续视觉方案，可复用同一检查行为。真实 Electron 测试覆盖未完成、重复检查已完成练习、未保存内容提醒及下一步跳转。视觉方向未确认，因此未发布新的安装包。

## 排版与落地约束

正文计划使用随应用打包的中文字体，减少 Windows 字体回退的不确定性；候选为思源黑体/Noto Sans SC，代码字体候选为 JetBrains Mono。正式纳入字体文件前核查具体来源及许可证。正文 16–18px、正文行距约 1.5–1.65，控件 14–16px；字体质量还取决于字重、行长、对比度和 Windows 缩放实测，不能只靠增大字号。

将选定方向实现为真实组件后，需要再验证中文、长文件名、长命令、不同窗口大小、200% 缩放，以及完成/未完成/检查失败状态。首版后端与隔离边界保持现有约束。

生成方式：内置 image_gen。原始提示见 [prompts.json](prompts.json)，针对 B/C 的定点修订见 [refinement-prompts.json](refinement-prompts.json)。
